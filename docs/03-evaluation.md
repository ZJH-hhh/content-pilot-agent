# 验证、失败与限制

## 已实际执行

- `npm test`：**40/40 通过**（含审计回归和有界超时配置）。完整输出见 [`examples/test-results.txt`](../examples/test-results.txt)。
- `npm run examples`：生成 **12 组**实际离线运行记录，汇总见 [`examples/summary.json`](../examples/summary.json)。
- `npm run evaluate:live`：使用配置的 `gpt-6.1-sol` 兼容接口实际运行，最终三场景全部通过；`npm run verify:live` 从原始记录独立复核通过。见 [真实报告](../examples/live/README.md)及 [最终 manifest](../examples/live/runs/2026-10-31T14-04-34-911Z-27e70588/manifest.json)。
- 浏览器验证：见 [`examples/browser-checks.md`](../examples/browser-checks.md)，记录与自动化测试分开列出。

这些不是预写决策日志。离线生成器实际执行 Agent 和四类本地工具，前 12 组记录明确标记为 `mock`。此外，`examples/live/runs/` 保存真实兼容接口的三次评估运行，含最终通过及之前两次未通过的原始记录；真实与离线证据分开存储。模型选择动作，业务素材、模板脚本、成本估算与保存仍是本地工具。

## 测试中发现的问题与修改

第一次完整测试为 23 通过、1 失败：Windows 下静态资源根目录带尾分隔符，路径边界检查再次附加分隔符，导致首页 404。将根目录先 `path.resolve` 规范化后，首页和资源测试通过。此项说明在浏览器检查前，HTTP 测试已发现真正的跨平台缺陷。

浏览器续跑检查还发现历史 stop 轨迹引用了任务的最新 reason，保存成功后会把旧的停止观察错误显示为「已保存」。已将每次决策的摘要固化到该条 Trace，前端兼容读取旧记录的独立 reason，并补充断言保证续跑后旧的停止摘要不变。

另一次受限环境运行被操作系统拒绝创建测试子进程（spawn EPERM）；在获准的执行方式下重跑后全部通过。这是环境限制，不统计为项目功能通过或失败。

## 无法据此得出的结论

1. 离线规则策略不是模型 ReAct 效果证据；不能以 12 组 Mock 全通过宣称真实模型验收通过。
2. HTTP 适配器测试使用伪造的网络响应，只证明报文结构与观察传递，不证明模型实际选择合理。
3. 没有对文案吸引力、发布效果、素材版权库覆盖率进行评估。
4. 单进程文件存储、轮询和完整上下文在小规模演示下可用；未做并发负载、长期耐久、断电恢复或生产安全评估。
5. 截止时间估算只计算素材表中的后续制作时间；工具实际执行耗时通过保存时重验覆盖，但没有独立的队列等待与并行资源模型。

## 真实模型复现与检查

配置密钥后运行 `npm run evaluate:live`，检查 `examples/live/` 的 normal、budget-replan、tool-failure 三条记录。至少两条应体现不同 observation 导致不同动作；预算调整须实际经历精选估算 12 后选择轻量 8。记录模型名、任务输入、实际轨迹、结果和失败，不以脚本替身代替真实调用。真实模型可能因行为不符合预期而失败，届时应如实记录并迭代提示或接口约束。

## 本轮审计后的行为验收

真实脚本现在将原始记录保存在 `examples/live/runs/<runId>/`，并自动检查预算 12→8 的先后依赖、失败后的替代动作、成功素材/脚本的保留、费用与截止时间，以及至少两种不同工具路径；仅有 completed 不再通过。运行 `npm run verify:live` 可从原始记录重新复核。该命令不调用模型。

新增 11 项校验器测试均使用明确标注的内存合成 fixture，测试反例包括：直接选轻量但未观察超预算、完成却没有真实失败步骤、缺模型元数据、陈旧观察、改写历史、删除成功产物、虚构费用、伪造保存依赖和混用不同 run。这些 fixture 从未写入 `examples/live/`，不能当作新增的真实模型证据。

初次执行 `verify:live` 因没有真实记录正确返回非零；`submission:check` 将真实证据、GitHub 信息和本人披露列为未完成。其结果见 [`examples/submission-status.json`](../examples/submission-status.json)。准确保留未完成项是审计修订的一部分，不把它们改成“全部通过”。
